# cvetrack 設計說明

## 1. 為什麼要「變化」

只看「這台主機現在有哪些弱點」，每次更新 OSV 或同步主機後只會得到一份新的清單，看不出：

- 這次多出來的弱點，是新公告的 CVE，還是有人裝了舊版套件？
- 消失的弱點，是有人修補了，還是官方改了資料（撤回、修正版本下修）？
- 修補是哪一張變更單做的？有沒有修補卻沒有單號的？

cvetrack 把每次匯入／同步當成一個 **Run**，和上一次成功的 Run 比較，差異記成**事件**，並判斷**原因**。

## 2. 資料

| 資料 | 說明 |
|---|---|
| OsvImport／Vuln／Affected／BinMap／UsnFix | Canonical OSV。每一列帶匯入編號：新的一份分批寫入（短交易），寫完才切換使用中的編號，舊資料再分批刪除 |
| AdvisoryChange | 這份 OSV 和前一份的差異（CVE × 套件庫 × source）：新增、移除、新增修正、修正被取消、修正版本變更、範圍變更、等級變更 |
| VexImport／VexStatus | Canonical VEX（官方處理狀態） |
| Host／HostPackage | 主機與目前的套件 |
| PackageChange | 這次 Run 主機有變的套件（只記差異）；執行中 kernel 換了也記一筆 |
| Finding | 目前狀態：主機 × CVE × 套件 × 位置（installed／running-kernel） |
| FindingEvent | 事件，只新增；唯一會改的是變更單號（改單號另記稽核） |
| ChangeTicket | 變更單：單號、說明、預計時間、預計主機 |

## 3. 事件與原因

判斷順序：主機狀態 → 套件有沒有變（PackageChange）→ OSV 有沒有變（AdvisoryChange）→ 其他。

| 事件 | 原因 | 判斷 | 要單號 |
|---|---|---|---|
| 初始 | 基準 | 第一個成功的 Run | — |
| 新出現／重新出現 | 新主機 | 主機第一次出現（或停用後回來） | — |
| | 主機套件變更 | 這個套件這次新裝或換了版本（例如降版） | 選填 |
| | 新公告 | 套件沒變，OSV 新增了這個 CVE | — |
| | 釋出修正 | 套件沒變，原本沒有修正（預設不列）、現在有修正版本 | — |
| | 公告修訂 | 套件沒變，OSV 改了範圍或修正版本 | — |
| 已解決 | 已修補 | 套件版本換了（升到修正版本以上）；或裝了新 kernel、舊 kernel 不再比對 | **必須** |
| | 已移除 | 套件被移除 | **必須** |
| | 已重開機 | 執行中 kernel 換成已修正的版本 | **必須** |
| | 公告修訂 | 套件沒變，OSV 撤回或修正版本下修 | — |
| | 主機移除 | 主機不在 Landscape 了 | — |
| 狀態變化 | 釋出修正 | 尚無修正 → 有修正 | — |
| | 修正版本變更 | 修正版本改了 | — |
| | 待重開機 | 套件已更新、執行中 kernel 還是舊的 | — |
| | 等級變更 | 官方等級改了 | — |
| 任何 | 其他 | 以上都不是（例如 Pro 狀態、kernel API 設定改變） | — |

特殊情況：

- kernel API 查詢失敗：執行中 kernel 的弱點保持未解決，不產生事件（不知道是否已重開機）。
- 例外（風險接受）涵蓋的事件照樣記錄，標「例外」。
- Run 失敗：已寫入的部分保留；下一次成功的 Run 仍和上一次成功的 Run 比較 OSV 差異。

## 4. 變更單

- **事後補號**：「待補單號」列出必須有單號、還沒有的事件；勾選或「符合篩選的全部」輸入單號。單號不存在就建立變更單。
- **先開單**：填預計主機與預計時間；之後同步到這些主機、在預計時間內（預設再寬限 24 小時）的修補事件，列在變更單的「建議對應」，**由人確認才掛上**。
- 改單號、移除單號都記在稽核紀錄。
- 報告：變更單明細（可匯出附在單後面）、超過 N 天沒補號的修補、過了預計時間卻沒有任何事件的變更單。

## 5. 與原專案共用 SQLite

- 匯入 OSV（數十萬到兩百多萬列）每 `IMPORT_BATCH`（預設 2 萬）列一個交易；切換使用中的資料只是一個 UPDATE。
- 比對結果一台主機一個交易（批次寫入）。
- 同一時間只有一個匯入／同步（檔案鎖）。
- 不執行 VACUUM（會鎖住整個資料庫）；刪除的空間會被之後的匯入重複使用。

## 6. 與 cvehub 的一致性

`tools/parity_hosts.py` 產生測試主機（真實套件清單加隨機降版、各 Ubuntu 版本、Pro／kernel 各種組合），
`tools/parity_compare.py` 用同一份 OSV 比較 cvehub 的 `evaluate_host` 和 cvetrack 的結果，要完全相同。
